I want to build a low code agent builder. It must have the following components

A UI graph builder with the following features

1. The UI will build a flow graph which defines an "agent".
2. The flow graph will be build from "steps".
3. Each step will have inputs and outputs
4. The inputs will come from a structured memory store
5. The outputs will write into the structured memory store
6. The steps can be connected to each other. The steps are the nodes in the
graph, the connections are the edges in the graph.
7. The edges represent the control flow through the graph
8. There should be a "start" step, an "llm" step and "output" step, a variety
of steps for manipulating data etc.
9. The steps should all have some common base class
10. It should be possible to add steps to the framework via some sort of
registration mechanism.
11. It should be possible to MCP. The "agent" step configuration will allow the
MCP definitions which can be used with it. It will also allow the selection of
tools which come with the system. It should be possible to register new tools.
Many of the steps themselves could be tools.
12. The UI should be concerned with building the graph and defining inputs and
outputs of each step.

The ui builder will be called the "graph-builder"

A mechanism to "compile" the graph into an actual running program. The
following compiler outputs should be possible

1. Turn the graph defined by the UI into a Pydantic AI based agent using pydantic AI
and pydantic AI graph

2. Turn the graph defined by the UI into a Langgraph/LangChain based agent

These python programs should run by themselves, with or with out a fastapi
frontend or run in the framework defined below.

The compiler componet will be called the graph-compiler. The graph-compiler
will generate standalone executable graphs (i.e. python programs), or it will
define a special executable which runs in the execution environment described
below. If possible the same generated code should be able to run standalone or
in the execution environment. Lets call the generate programs graph-programs.

The final component should be an agent execution environment. It will ba a long
running fastapi based service which is capable of managing and running the
agents generated by the compiler define above. 

1. The fast api server will allow compiled agents to be executed
2. It should be possible to stop any runnign agent
3. It should be possible to pass context (initializes the input part of the
memory store) into the agents
4. It should be possible to query the memory store at any point of the
execution
5. The agents could be log running

Lets call this component the graph-runtime-manager.

More about the "memory store", when the UI builds the graph it will also be
defining the structure of the memory store. The memory store should have the
following components

1. Inputs - these are values that will be populated when the agent actually
runs. So passed into the compiled graphs or passed in via the execution
environment.

2. Outputs - These respresents outputs from the flow graphs

3. Intermediate storage - this is were steps can output results or reference
results from other steps.

4. Secrets - there should be a place where secrets are stored which will be
managed in a safe manner.

The graph-runtime-manager will manage multiple memory stores for each running
instance of a graph-program.
